## What was changed

**`src/shaders/shadow.frag`**, the hard cutout replaced with the sphere-tracing loop:

```glsl
#ifdef GL_ES
precision highp float;
#endif

varying vec2 vTexCoord;
uniform vec2 uResolution;
uniform vec2 uLight;
uniform vec2 uCharlie;

void main() {
  vec2 uv = vTexCoord;

  vec2 toLight = uLight - uv;
  float totalDist = length(toLight);
  vec2 dir = normalize(toLight);

  float t = 0.01;
  float shadow = 1.0;

  for (int i = 0; i < 64; i++) {
    vec2 p = uv + dir * t;
    float h = length(p - uCharlie) - 0.08;

    if (h < 0.0) { shadow = 0.0; break; }

    shadow = min(shadow, 8.0 * h / t);

    t += max(h, 0.005);
    if (t >= totalDist) break;
  }

  gl_FragColor = vec4(vec3(shadow), 1.0);
}
```

No changes to `main.js` or any other file.

## The math: where each line comes from

### The setup: ray from fragment toward light

```glsl
vec2 toLight = uLight - uv;
float totalDist = length(toLight);
vec2 dir = normalize(toLight);
```

For every fragment, we compute the direction to the light and how far away it is. We'll march a ray in that direction and stop when we reach `totalDist`. Beyond the light, nothing matters.

### Starting position

```glsl
float t = 0.01;
```

We start the march slightly off the fragment surface (not at `t = 0.0`) because at `t = 0.0` we're exactly at the fragment. If the fragment is on the edge of Charlie's SDF, `h` could evaluate to zero or negative immediately, creating a false self-shadow. The `0.01` offset avoids this.

### The Quilez near-miss estimator

```glsl
shadow = min(shadow, 8.0 * h / t);
```

This is the core formula from [3] Quilez. At each step along the ray:

- `h` = the SDF distance to Charlie at the current sample point. How close the ray came to hitting Charlie.
- `t` = how far along the ray we've marched. How far from the fragment we are.

The ratio `h / t` measures the angular width of the gap between the ray and Charlie's surface at that step. A small `h` relative to `t` means the ray barely missed Charlie: the shadow should be dark. A large `h` means a clean miss: full light.

The `8.0` multiplier is the sharpness constant `k`. Higher k = harder shadow edges. Lower k = softer penumbra.

`min(shadow, ...)` accumulates the darkest near-miss across the entire march. The shadow factor is determined by the step where the ray came closest to Charlie.

### Sphere stepping

```glsl
t += max(h, 0.005);
```

At each step, we know the scene is clear at least to distance `h` (that's what the SDF guarantees: no geometry within radius `h` of this point). So it's safe to jump `h` forward without missing anything. This is sphere stepping: the same principle as Hart (1996) applied to 2D.

The `max(h, 0.005)` prevents an infinite loop when `h` is very small: we always advance at least 0.005 per step.

### Hit condition

```glsl
if (h < 0.0) { shadow = 0.0; break; }
```

If `h` goes negative, the ray is inside Charlie's circle. That's a direct hit. Full shadow, no need to continue marching.

## Why the spokes appear

The spokes are real geometry, not an artifact to fix. Charlie is a single circular occluder. The shadow cone around it has a defined angular width. For fragments just outside that cone, the ray passes cleanly to the light. For fragments inside the cone, it hits Charlie.

At the boundary (the penumbra), the near-miss factor `8.0 * h / t` creates the soft gradient. But because Charlie is a perfect circle with a single smooth SDF, the penumbra has a specific angular shape that creates the spoke pattern.

This will be softened in Step 7 (post-processing blur) but is not a bug.

---

## Why light close to Charlie looks dramatic

When the light source is close to Charlie, the shadow cone subtends a wider angle: Charlie blocks more of the hemisphere visible from any given fragment. Fragments that were previously in partial light are now deep in the penumbra.

This is the horror mechanic. In Step 8, Charlie Chat will move toward the player. As proximity decreases, the shadow expands and the light-cone collapses.
