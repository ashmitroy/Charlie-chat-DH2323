# Entry 08: SDF shadow working. Charlie Chat exists.

## What happened

Charlie Chat is now visible. Not as a sprite, as a dark circle cut into the lit environment by mathematics. Move the mouse (the light). The scene responds. The dark SDF shape sits in the center, multiplied over the N·L lighting.

This is the first time all three things exist simultaneously: a surface with normal-mapped lighting, a point light that moves, and a shadow shape.

## What was built

Two new files: `shadow.vert` and `shadow.frag`. One new shader variable and two new uniforms in `main.js`.

**`src/shaders/shadow.vert`**, identical to `sobel.vert`, standard vertex passthrough:
```glsl
attribute vec3 aPosition;
attribute vec2 aTexCoord;
varying vec2 vTexCoord;

uniform mat4 uModelViewMatrix;
uniform mat4 uProjectionMatrix;

void main() {
  vTexCoord = aTexCoord;
  gl_Position = uProjectionMatrix * uModelViewMatrix * vec4(aPosition, 1.0);
}
```

**`src/shaders/shadow.frag`**, the SDF circle:
```glsl
#ifdef GL_ES
precision highp float;
#endif

varying vec2 vTexCoord;
uniform vec2 uResolution;
uniform vec2 uLight;
uniform vec2 uCharlie;

void main() {
  vec2 uv = vTexCoord;

  float d = length(uv - uCharlie) - 0.08;

  float shadow = d < 0.0 ? 0.0 : 1.0;

  gl_FragColor = vec4(vec3(shadow), 1.0);
}
```

**`src/js/main.js`**, shadow pass added to `draw()`:
```javascript
blendMode(MULTIPLY);
shader(shadowShader);
shadowShader.setUniform('uResolution', [width, height]);
shadowShader.setUniform('uLight', [mouseX / width, mouseY / height]);
shadowShader.setUniform('uCharlie', [0.5, 0.5]);
plane(width, height);
blendMode(BLEND);
```

`uCharlie` is hardcoded to `[0.5, 0.5]`, center of the screen in UV space. This will be driven by keyboard input in Step 8 when the game loop is built.

---

## The math: where each line comes from

### `float d = length(uv - uCharlie) - 0.08`

This is the **Signed Distance Field (SDF) for a circle**, from [3] Quilez SDF primitives.

- `length(uv - uCharlie)` = Euclidean distance from the current pixel to Charlie Chat's center
- `- 0.08` = subtract the radius (0.08 in UV space ≈ 77px on a 960px canvas)
- Result: positive = outside the circle, zero = on the edge, negative = inside

This is the same formula understood in Entry 02 conceptually. This is the first time it runs in actual GLSL.

### `float shadow = d < 0.0 ? 0.0 : 1.0`

Hard cutout. Inside the circle → black (0). Outside → white (1). No soft falloff yet: that's the Quilez raymarcher, which comes in a later step.

### `blendMode(MULTIPLY)`

The shadow shader outputs fully opaque black/white. Without a blend mode, this would replace the lit scene entirely. With MULTIPLY:
- White (1, 1, 1) × lit scene = lit scene unchanged
- Black (0, 0, 0) × lit scene = black

Charlie Chat becomes a dark hole cut into the lit environment. The lighting underneath is still computed. It just gets multiplied to zero inside the circle.

## The debug: what broke and why

The pipeline broke completely after adding the shadow shader. The N·L lighting stopped responding to the mouse. The screen went stuck at the top-left corner.

**Root cause:** `shadow.vert` I created and forgot to populate it. `loadShader()` loaded an empty string as the vertex shader source and passed it to the GPU compiler. An empty vertex shader is invalid GLSL: no `void main()`, no `gl_Position`. The GPU rejected it immediately.

When a shader fails to compile in WebGL, the whole shader program becomes invalid. `shader(shadowShader)` then put the GPU into a broken state. This corrupted the WebGL context for the rest of `draw()`, affecting the N·L pass that ran in the next frame, even though the N·L shader itself was untouched.

**The fix:** Populated `shadow.vert` with the standard vertex passthrough, identical to `sobel.vert`. One file, 10 lines. The N·L lighting and mouse tracking both came back immediately.

**The rule this teaches:** In a multi-shader pipeline, a broken shader doesn't just break its own pass: it can corrupt the WebGL state for every subsequent draw call in that frame and carry into the next. Always verify both `.vert` and `.frag` files exist and compile before adding a new shader to the pipeline.

## Why this matters for the project

Charlie Chat is now a rendered entity. No texture, no sprite, no asset file. Just a position (`uCharlie`) and a radius (0.08) passed to a formula. Every frame, 518,400 pixels each ask: "am I inside this circle?" and receive a yes or no.

This is what makes the horror mechanic possible. In Step 8, `uCharlie` gets driven by proximity to the player: the closer the player, the larger the shadow. The SDF radius will grow. The darkness will spread.

The current output is a hard black circle. What's coming:
- **Soft edges**: Quilez soft-shadow raymarcher replaces the hard cutout
- **Proximity-driven size**: `uCharlie` radius animates from player distance
- **Multiple shadow casters**: `min()` of multiple SDFs
