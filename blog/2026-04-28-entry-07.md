# Entry 07: Multi-pass pipeline working

## What happened

The pipeline is now multi-pass. The lit environment renders offscreen into a framebuffer, then gets painted to the screen, then a second layer composites on top of it. This is the architectural foundation everything else plugs into: SDF shadow, post-processing, sprites. All of it adds as additional passes over this same structure.

The test: an orange rectangle drawn flat on top of the lit environment. No shader on the rectangle, just p5's default renderer. It composited cleanly over the N·L lighting pass. Test rectangle removed once proven.

## What changed in `main.js`

Three additions. The shader and height map code didn't change at all.

**New variable:**
```javascript
let fb;
```

**In `setup()`, one new line:**
```javascript
fb = createFramebuffer();
```

**`draw()` restructured into two passes:**
```javascript
function draw() {
  fb.begin();
  shader(myShader);
  myShader.setUniform('uResolution', [width, height]);
  myShader.setUniform('uHeightMap', heightMap);
  myShader.setUniform('uMouse', [mouseX / width, mouseY / height]);
  plane(width, height);
  fb.end();

  clear();
  resetShader();
  image(fb.color, -width / 2, -height / 2, width, height);
}
```

---

## What each new thing does

**`createFramebuffer()`**: allocates an offscreen render target the same size as the canvas. Nothing is drawn into it yet: it's an empty texture waiting to receive pixels.

**`fb.begin()` / `fb.end()`**: everything drawn between these two calls goes into the framebuffer instead of the screen. The shader runs identically. The only difference is destination.

**`clear()`**: wipes the screen before the second pass draws onto it.

**`resetShader()`**: switches back to p5's built-in default shader. After calling `shader(myShader)` inside the framebuffer pass, the custom shader is still active. Without `resetShader()`, any subsequent draw call would try to use our GLSL and fail or produce garbage.

**`image(fb.color, -width/2, -height/2, width, height)`**: paints the framebuffer's colour attachment as a flat image onto the screen. `fb.color` is a `p5.Texture`, the exact pixels that were rendered in Pass 1.

The `-width/2` offset: in WEBGL mode, the canvas origin (0, 0) is the centre of the screen, not the top-left. So to draw a full-screen image starting from the top-left corner, we offset by half the canvas dimensions in both directions.

---

## Why this is the critical architectural step

Every effect from here adds as a new pass:

```
Pass 1 (done): environment shader → fb
Pass 2 (done): fb.color → screen
Pass 3 (next): SDF shadow shader reads scene, composites shadow over it
Pass 4: post-processing reads full composited frame
```

The sprite layer (Charlie, NPCs) inserts between Pass 2 and Pass 3, drawn flat with `resetShader()` active, directly onto the screen over the lit environment, before the shadow pass runs.

Without the framebuffer, all of this would have to happen in one shader. One shader cannot both compute lighting AND compositing AND shadows AND post-processing: it only knows about one pixel at a time and has no memory of what was drawn before. The framebuffer is how passes share data.
