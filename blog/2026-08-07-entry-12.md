## Three states

`'start'` → `'playing'` → `'gameover'`

Before this: no states. One continuous draw loop, no beginning, no end. Adding the guard was the first thing:

```javascript
function draw() {
  if (gameState !== 'playing') return;
  // everything else
}
```

Now `draw()` only runs when it's supposed to. The other two states are handled by DOM overlays  HTML sitting on top of the canvas, not GLSL inside it. That decision took a detour to arrive at.

## The start screen

I tried doing the game over text in WEBGL mode first. p5.js has `text()` in WEBGL but the coordinate system is 3D origin at canvas center, not top-left and you have to call `resetShader()` before any 2D drawing, which disturbed the pipeline state. The text appeared in the wrong place. Then the shader didn't recover cleanly for the next frame. Spent 40 minutes on it before accepting that the DOM is just the right tool for this.

A `<div>` over the canvas with `position: fixed`. The canvas renders behind it. `noLoop()` freezes the canvas. Zero shader involvement.

For the start screen, I wanted a retro terminal feel the kind you get in old PC horror games before anything happens. Not a designed UI. Something that feels like a system booting.

## Game over

When `dist < 0.035`, Charlie is roughly 34px from the player on a 960px canvas:

```javascript
if (dist < CATCH_DIST) {
  gameState = 'gameover';
  gameOverEl.classList.add('visible');
  noLoop();
  return;
}
```

`noLoop()` stops the draw loop. The WebGL context holds the last rendered frame on the canvas: the exact composition at the moment Charlie arrived. The overlay fades in on top of that frozen image over about 0.9 seconds.

## `renderScene()` why this extraction mattered

All the rendering logic was inline in `draw()`. I needed to call it once in `setup()` to produce a static frame visible behind the start screen before the game begins and then stop the loop. That's not possible when the rendering is fused to the game loop.

```javascript
function renderScene(shadowRadius) {
  fb.begin();
  background(0);
  // Pass 1: sobel
  // Pass 2: shadow (MULTIPLY)
  fb.end();
  // Pass 3: post
}
```

Now `setup()` calls `renderScene(0.05)` once, gives the canvas a static frame, then `noLoop()`. The start screen appears on top of that frame. When the player dismisses it, `resetGame()` calls `loop()` and the game begins. The canvas was never black behind the terminal: it had a floor in it the whole time.

## Cleanup

`hello.frag` and `hello.vert` deleted. They were the very first shaders from Entry 04, the UV gradient proof-of-concept. Nothing referenced them anymore. They'd been sitting in `src/shaders/` for three months pointing at nothing.

The function indentation in `main.js` was off throughout two extra spaces on every function body, leftover from an earlier version where everything was wrapped in an outer function that got removed. Fixed it.

The canvas was rendering in the top-left corner of the page. Added `display: flex; align-items: center; justify-content: center; min-height: 100vh` to `body`. Now it's centered.

Small things. None of them took long. But opening the code after two months and seeing dead files and misaligned indentation and an off-center canvas  cleaning that up was the first act.
